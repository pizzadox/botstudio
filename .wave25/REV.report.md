### IMP-25-REV-1 [minor] src/components/studio/orders-view.tsx:3812-3828 — bulk-ответ читается без crewUpdated: назначение экипажа в архивной вкладке показывает «Обновлено заявок: 0»
Бэк (IMP-25-05) применяет crewId ко ВСЕМ найденным заявкам независимо от статусных skip'ов и возвращает `crewUpdated`, но FE декларирует только `{ ok, updated, skipped }`. Кейс: вкладка «Архив» (финальные статусы), выделить строки, назначить экипаж → `updated=0`, `crewUpdated=N` → тост «Обновлено заявок: 0» без упоминания, что экипаж реально назначен (данные при этом корректны — `load()` перезагружает список). Также crew-only пачка по несуществующим id даёт skipped>0 с ложной подписью «недопустимый переход» (бэк считает «не найдено/чужие» тем же счётчиком).
**Фикс:** в типе ответа добавить `crewUpdated?: number` и в тост включать: `description: [skipped>0 && `Пропущено: ${skipped}`, crewUpdated>0 && `Экипаж назначен: ${crewUpdated}`].filter(Boolean).join(' · ') || undefined`; при `updated===0 && crewUpdated>0` — заголовок «Экипаж назначен заявок: N».

### IMP-25-REV-2 [minor] src/components/studio/complaints-view.tsx:764-771 — merge-поллинг никогда не удаляет записи, выпавшие из фильтра: в отфильтрованном списке остаются устаревшие карточки
Merge-режим (IMP-25-23) только добавляет/обновляет по id. Если статус жалобы изменился вне этой вкладки (коллега/поллинг карточки — PATCH статуса уже бэк side) и она перестала матчиться активному фильтру (напр. «Новые»), incoming-страница её не содержит, `prev.filter` её сохраняет → карточка «Решена» навсегда висит в чипе «Новые», пока оператор не сменит фильтр. В волне 24 жёсткая перезагрузка такое убирала — это осознанный trade-off merge, но чистится дёшево.
**Фикс:** в merge-ветке удалять из `prev` элементы, которых нет в `d.items`, но чей `createdAt >= d.items[d.items.length-1].createdAt` (они обязаны были попасть в первую страницу) — граница страницы известна, догруженный «хвост» не трогается; альтернатива — каждый N-й тик (напр. 10-й) делать hard-`load()`.

### IMP-25-REV-3 [minor] src/lib/wish-date.ts:253-262 (RE_DM) и 263-282 (RE_DD_MONTH) — «29 февраля» / «29.02» без года в невисокосный год по-прежнему NOT MATCHED

То же в RE_DM (:259-260). Смоук-подтверждено (2 TZ).
**Фикс:** после неудачи пробовать следующий год: `if (validYMD(year, mo, d)) target = {y: year, m: mo, d}; else if (validYMD(year + 1, mo, d)) target = {y: year + 1, m: mo, d};` (для «29.02» / «29 февраля» любой невисокосный «сегодня»).
